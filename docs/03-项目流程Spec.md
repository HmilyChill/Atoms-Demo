## 2. 术语表

| 术语 | 含义 |
|---|---|
| **Run** | 一次"从需求到产物"的生成执行；有状态、可取消、可重试 |
| **Spec / App Spec** | 对"要生成的应用"的结构化描述（页面/组件/数据模型/动作/校验/主题），是**唯一可执行真源** |
| **Artifact** | Agent 产出的中间物（计划、契约、页面清单、数据模型、Spec、验证报告、导出包） |
| **Contract（需求契约）** | 生成前锁定的"必做 / 禁做 / 验收点"清单，用于防止需求漂移 |
| **Verifier** | 质量校验智能体：结构校验 + 渲染冒烟 + 契约逐条核对 |
| **Version** | 一次 Spec 快照，支持回滚 |
| **Gate** | 阶段退出条件；不过不进下一阶段 |
| **DoD** | Definition of Done，阶段/模块的完成定义 |
| **Mock 提供方** | 不依赖真实 LLM 的确定性产出，用于演示兜底与自动化测试 |
| **降级（Degrade）** | 主链路不可用时的预设替代路径，必须对用户**显式可见** |

## 3. 系统架构与职责边界

| 层 | 职责 | 禁止事项 |
|---|---|---|
| **① 表现层** | 三栏界面：会话/Agent 时间线、产物区、实时预览；状态与错误呈现 | 不得直接调用 LLM；不得绕过 API 直接读库 |
| **② API 层** | Route Handlers：鉴权、项目/会话、Run 启动与事件流、产物读取、导出 | 不得内联业务编排逻辑（编排属于 ③） |
| **③ 编排层** | Run 状态机、步骤调度、事件广播、重试与超时、配额熔断 | 不得依赖 HTTP 请求上下文存活（须可跨请求续跑） |
| **④ 智能体层** | Planner / PM / Architect / Engineer / Verifier 五类角色，各自输入输出契约化 | 不得直接访问数据库；不得绕过适配器调用外部服务 |
| **⑤ 生成物运行时** | Spec 渲染器（Spec → 可交互应用）、预览沙箱、生成物数据读写 | 不得依赖宿主内部状态（只吃 Spec + 数据 API） |
| **⑥ 适配器层** | LLM 适配器 / 存储适配器 / 预览适配器 | 上层不得出现具体 provider 名称的分支判断 |
| **⑦ 基础设施** | 托管数据库、Vercel 部署、环境变量、日志 | 密钥不得出现在客户端或仓库 |

**核心设计原则**：把一切**不确定性**（有没有 key、用哪个 provider、用哪个数据库、是否回退到方案 A）关进 ⑥ 适配器层，使这些变化都成为**配置项**而非重写。

## 4. 核心数据模型

> 约定：所有实体含 `id`、`createdAt`、`updatedAt`；`schemaVersion` 用于兼容旧数据（见 §10 约束）。

| 实体 | 关键字段 | 说明 |
|---|---|---|
| **User** | `email`（唯一）、`passwordHash`、`displayName` | 密码只存哈希，绝不存明文 |
| **Project** | `ownerId`、`name`、`schemaVersion`、`currentSpecVersion` | 一个用户多个项目；项目的当前 Spec 版本指针 |
| **Session** | `projectId`、`title`、`status` | 一个项目多个会话（多轮迭代的载体） |
| **Message** | `sessionId`、`role`、`content`、`runId?` | 对话历史；用户消息与 Agent 消息 |
| **Run** | `sessionId`、`status`、`stage`、`startedAt`、`finishedAt`、`errorCode`、`tokenUsage` | 一次生成执行；**必须可跨请求恢复** |
| **Artifact** | `runId`、`type`、`payload`、`summary` | type ∈ {plan, contract, pages, dataModel, spec, doc, verification, export} |
| **SpecVersion** | `projectId`、`version`（自增）、`spec`、`parentVersion`、`changeSummary` | 版本链，支持回滚 |
| **AppRecord** | `projectId`、`collection`、`data` | **生成的应用内部的数据**（与宿主数据同库，保证"数据真的存下来了"） |
| **EventLog** | `runId`、`eventId`（单调递增）、`type`、`payload` | 事件流持久化，支持断线续传与回放 |

**关系**：`User 1─N Project 1─N Session 1─N (Message | Run)`；`Run 1─N Artifact`；`Project 1─N SpecVersion`；`Project 1─N AppRecord`。

**必须满足的约束**
1. `schemaVersion` 必须存在于 `Project` 与 `SpecVersion`；打开旧版本时必须**兼容读取或明确提示**，不允许静默失败。
2. `AppRecord` 与宿主数据**同一持久层**——这是"数据持久化"最容易被评审验证的部分。
3. `Run` 的中间状态必须落库，使**生成中刷新页面后能恢复**。

## 5. API 契约

> 统一约定：JSON 交互；鉴权用 HttpOnly Cookie；所有响应含 `traceId`。
>
> **下表已与实现逐条对齐**（业务路由 29 条 = 下表全部行；`pnpm build` 的清单共 31 条，
> 另 2 条是 Next 内部页 `_not-found` / `_global-error`）。
> 早期版本的本表曾列出一条 **从未实现** 的 `POST /api/runs/:id/repair`（已删除）；
> 修复动作实际由编排器在 `step` 内部按上限自动执行，不需要单独接口。

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/auth/register` | 注册 |
| POST | `/api/auth/login` | 登录 |
| POST | `/api/auth/logout` | 退出 |
| GET | `/api/auth/me` | 当前用户（**一键体验**的演示账号也走这里） |
| POST | `/api/auth/demo` | **一键体验**：创建演示账号并登录 |
| GET | `/api/health` | 健康检查（含当前 provider 与是否降级为 Mock） |
| GET / POST | `/api/projects` | 列出 / 新建项目 |
| GET / PATCH / DELETE | `/api/projects/:id` | 项目详情 / 重命名 / 删除 |
| GET / POST | `/api/projects/:id/sessions` | 会话列表 / 新建会话 |
| POST | `/api/runs` | 启动一次生成，返回 `runId` |
| GET | `/api/runs/:id` | Run 快照 + 产物列表（**事件丢失后对齐，也是"产物归约"的数据源**） |
| POST | `/api/runs/:id/step` | **推进一步**（短步骤执行，前端循环调用以规避函数超时） |
| GET | `/api/runs/:id/events` | **SSE 事件流**（支持 `Last-Event-ID` 续传，可回放） |
| POST | `/api/runs/:id/confirm` | 确认计划/契约，继续执行 |
| **POST** | **`/api/runs/:id/contract`** | **在 Gate（`awaiting_confirm`）阶段修订契约并重新锁定**；非 Gate → 409；不许凭空新增机检项 / 删光必做项 / 清空验收点 → 400 |
| POST | `/api/runs/:id/cancel` | 中断 |
| GET | `/api/projects/:id/spec` | 读取当前或指定版本 Spec（含 `schemaVersion` 兼容检查） |
| GET | `/api/projects/:id/diff` | **版本结构差异**（`?from=&to=`；"只改目标片段"的可见证据） |
| POST | `/api/projects/:id/versions/:v/rollback` | 回滚到指定版本（**以新版本追加，历史不删除**） |
| GET | `/api/projects/:id/preview-token` | 申请短期**预览令牌**（沙箱 iframe 无同源 → 不能靠 Cookie） |
| POST | `/api/projects/:id/share` | 生成 / 读取**只读分享**链接 |
| GET | `/api/projects/:id/export` | 导出（默认 / `?format=html` → **单文件 HTML**；`?format=zip` → **多文件工程 ZIP**） |
| GET / POST | `/api/projects/:id/records/:collection` | 生成应用的数据读写（列表 / 新增） |
| PATCH / DELETE | `/api/projects/:id/records/:collection/:recordId` | 生成应用的数据更新 / 删除 |

**错误码约定**

| 码 | 含义 | 前端行为 |
|---|---|---|
| 400 | 参数错误（含**被拒绝的契约修订**） | 就地提示 |
| 401 | 未登录 | 跳登录 |
| 404 | 不存在 **或越权访问他人资源** | 友好空态（**越权也用 404，不泄露资源是否存在**，见下方说明） |
| 409 | 状态冲突（如 Gate 之后改契约、Run 已结束） | 刷新状态 |
| 422 | 校验失败（如 Spec 不合法） | 展示可读原因 |
| 429 | 触发限流/配额 | 提示"演示额度已用完，可切换演示模式" |
| 500 / 503 | 内部错误 / Provider 不可用 | 提示 + 提供降级路径 |

> ⚠️ **本表曾写"403 越权"**，但实现选择的是 **404**：`requireProjectForOwner()` 在项目不属于当前用户时抛 `NOT_FOUND`。
> 403 会泄露"该 id 确实存在、只是你没权限"，404 则让"不存在"和"不是你的"无法区分——这是**有意为之**，
> 并有回归测试锁死（`tests/isolation.test.ts`）。文档此处已按实现更正。

## 6. 事件协议（Run 的可观测性基础）

| 事件名 | 触发时机 | 载荷关键字段 |
|---|---|---|
| `run.started` | Run 创建 | `runId`, `sessionId` |
| `plan.ready` | 计划产出 | `artifactId`, `summary` |
| `contract.ready` | 需求契约产出（**用户改过契约时 `revised: true` 再发一次**） | `mustDo[]`, `mustNot[]`, `acceptance[]`, `revised?` |
| `agent.started` | 某角色开始 | `agent`, `stage` |
| `agent.delta` | 流式输出片段 | `agent`, `chunk` |
| `agent.finished` | 某角色结束 | `agent`, `durationMs`, `tokenUsage` |
| `spec.ready` | App Spec 产出 | `version`, `pageCount` |
| `preview.updated` | 预览可刷新 | `version`, `entryUrl` |
| `verify.started` | 校验开始 | `checkCount` |
| `verify.result` | 校验完成 | `passed[]`, `failed[]`, `severity` |
| `repair.attempt` | 触发修复 | `round`, `reason` |
| `run.finished` | 成功收敛 | `version`, `totalMs`, `tokenUsage` |
| `run.failed` | 失败 | `errorCode`, `message`, `stage` |
| `run.cancelled` | 用户中断 | `stage` |

**协议原则**（必须遵守）
1. **事件可丢，状态不可丢**：前端任何时候都能用 `GET /api/runs/:id` 快照对齐，事件只是增量优化。
2. `eventId` 单调递增，支持 `Last-Event-ID` 断线续传。
3. 每个 `agent.started` 必须有配对的 `agent.finished` 或 `run.failed`——**不允许出现"永远转圈"的 Agent 卡片**。

## 7. 智能体编排流水线

| 顺序 | 角色（对标 Atoms） | 输入 | 输出契约 | 失败处理 |
|---|---|---|---|---|
| 1 | **Planner**（团队领导 Mike） | 用户需求 + 项目上下文 | 计划 + **需求契约**（必做/禁做/验收点） | 产出不合法 → 重试 1 次 → 降级为模板契约 |
| 2 | **PM**（Emma） | 已确认的契约 | 页面清单 + 信息架构 | 同上 |
| 3 | **Architect**（Bob） | 页面清单 | 数据模型 + 动作 + 页面字段绑定 | 同上 |
| 4 | **Engineer**（Alex） | 以上全部 | **App Spec**（结构化，见 §8） | 结构不合法 → 带错误信息重试，上限 2 次 |
| 5 | **Verifier**（QA，我们的差异化） | Spec + 契约 | 校验报告（通过项/失败项/严重级别） | 校验器自身异常 → 标记"未校验"，**不得谎报通过** |
| 6 | **Repair**（条件触发） | 失败项 | 修补后的 Spec | 最多 2 轮；超限则如实上报"部分通过 + 原因" |

**Gate**：第 1 步产出契约后**暂停等待用户确认**（可配置为自动确认以支持一键演示）。

**成本与稳定性控制（硬约束）**
- 单次 Run 的 LLM 调用次数上限（建议 12 次），超限即中止并如实报错。
- 每次调用有超时；失败重试上限 2 次；重试仍失败 → 走降级。
- 所有调用记录 token 用量与耗时，进入 `Run.tokenUsage` 与日志。

## 8. 应用 Spec 规格（表达力边界与诚实原则）

**顶层结构**

| 字段 | 说明 |
|---|---|
| `meta` | `schemaVersion`、应用名、描述、生成时间 |
| `theme` | 主题令牌（主色、圆角、密度、明暗） |
| `dataModels` | 集合名 + 字段定义（类型、必填、默认值、校验规则） |
| `pages` | 页面列表：路由、标题、布局、组件序列 |
| `components` | 组件白名单实例（见下），含数据绑定与动作绑定 |
| `actions` | 可执行动作（创建/更新/删除/筛选/跳转/提交） |
| `navigation` | 导航结构（侧边栏/顶栏/标签页） |
| `validations` | 字段级与表单级校验规则 |

**组件白名单（P0 表达力边界）**

| 类别 | 组件 |
|---|---|
| 布局 | Page、Section、Grid、Tabs、Modal、Drawer |
| 数据展示 | Table、List、Card、Detail、Stat、Chart（柱/折线/饼） |
| 输入 | Input、Textarea、Select、MultiSelect、DatePicker、Checkbox、Switch、Upload（仅文件名） |
| 操作 | Button、IconButton、SearchBar、FilterBar |
| 反馈 | EmptyState、Loading、ErrorState、Toast |

**诚实原则（硬性）**
1. 需求超出白名单时，**必须明确报错并说明不支持**，不允许静默降级成近似物。
2. 任何"未实现/未校验/部分完成"的状态都必须在 UI 与产物中**显式标注**。
3. **禁止假按钮**：界面上出现的控件必须有效，否则不渲染。

## 9. 阶段划分（S0–S9）

> 每个阶段都是可独立交付、可中断、可验收的单元。**估时压力与修正方案见 `01` §8。**
>
> ✅ **档位已定：完整档（9–10h）→ S0–S9 阶段全部执行**，含 S6（迭代+版本）、S7（校验自愈）、S8（导出与分享）。
> **降档预案**（仅当实际时间不足时启用，顺序不可颠倒）：**① 砍 S7 → ② 砍 S8**；S0–S6 与 S9 为不可砍的核心。
> 模块与阶段的对应关系、以及每阶段的具体子任务，见 `04-模块实现细则与验收标准.md`。

### S0 · 前置与冻结 ⏱ 45min
- **目标**：把所有"环境类不可逆风险"在第一小时清零。
- **前置**：用户提供 GitHub 令牌与 DeepSeek key。
- **动作**：建 public 仓库 → **部署空壳并拿到公网链接** → 配置环境变量 → **DeepSeek 连通性与结构化输出验证** → 冻结范围与验收清单。
- **产出**：可访问的空壳链接、仓库、环境变量就绪、一次合法结构化输出的证据、范围冻结清单。
- **DoD/Gate**：① 公网链接可打开；② DeepSeek 成功返回一次符合约定的结构化结果；③ 密钥已确认不在仓库内。
- **降级**：Provider 不通 → 先用 Mock 推进，但**必须记录并继续排查**，不得静默跳过。

### S1 · 骨架 + 存储适配器 + 身份与项目 ⏱ 90min
- **对应模块**：M9、M1，以及 **LLM 适配器**（从 M4 前置拆出，见 `01` §8 修正）
- **产出**：三栏页面骨架；数据模型落库；注册/登录；项目列表与新建。
- **DoD/Gate**：注册 → 建项目 → 刷新后仍在 → 换浏览器登录后仍在。
- **降级**：托管 DB 不可用 → 切本地 SQLite（开发）/ 或临时 IndexedDB 适配器。

### S2 · 需求输入 + 计划与契约 ⏱ 60min
- **对应模块**：M2、M3
- **产出**：对话输入区；Planner 产出计划与需求契约；用户可确认或纠偏。
- **DoD/Gate**：未确认不执行；契约以"必做/禁做/验收点"三段呈现且可编辑。
- **降级**：契约生成失败 → 使用模板契约（仍可继续）。

### S3 · 编排引擎 + 事件流 ⏱ 90min
- **对应模块**：M4
- **产出**：Run 状态机、五角色依次产出 Artifact、SSE 事件流、取消与重试、配额熔断。
- **DoD/Gate**：至少 3 个角色可见且状态正确；任一环节失败可重试且状态一致；**无"永远转圈"的卡片**。
- **降级**：SSE 不可用 → 轮询 `GET /api/runs/:id`（功能等价，体验略降）。

### S4 · App Spec 与渲染运行时 ⏱ 120min ★技术心脏
- **对应模块**：M5
- **产出**：Spec → 可交互应用的确定性渲染器；组件白名单实现；生成物数据读写打通。
- **DoD/Gate**：同一 Spec 两次渲染结果一致；生成的表单能提交、列表能新增、**数据刷新后仍在**。
- **降级**：个别组件未实现 → 从白名单移除并明确报错（禁止静默近似）。

### S5 · 预览沙箱 + 错误回传 ⏱ 60min
- **对应模块**：M6
- **产出**：iframe 沙箱预览、宿主↔预览双向消息、**预览内运行时错误回传并显示**、加载/错误态。
- **DoD/Gate**：人为注入一个错误，宿主能显示明确错误而非静默白屏。
- **降级**：沙箱通信受限 → 降级为"重新装载 + 宿主侧错误边界"。

### S6 · 迭代修改 + 版本管理 ⏱ 50min（延展能力 · 精简版）
- **对应模块**：M7
- **产出**：对已生成应用继续提需求 → 增量修改 Spec → 生成新版本 → 一键回滚。
- **DoD/Gate**：第二轮修改只影响目标片段；回滚后恢复上一版且**数据不丢**。
- **降级**：增量定位失败 → 退回"全量重生成 + 新版本"（仍保留版本能力，不做 diff 视图）。

### S7 · 校验与自愈 ⏱ 40min（差异化亮点 · 精简版）
- **对应模块**：M8
- **产出**：结构校验 + 渲染冒烟 + **契约逐条核对**；失败自动修复（上限 2 轮）；如实上报。
- **DoD/Gate**：故意构造不满足契约的 Spec，系统能检出并修复，或**如实报错**。
- **降级**：修复循环超时 → 停止修复，输出"部分通过 + 未通过项清单"。

### S8 · 导出与分享 ⏱ 40min
- **对应模块**：M10 的一部分（呼应生成策略 ③）
- **产出**：导出可运行源码包（可下载）；可选只读分享链接（随机 token）。
- **DoD/Gate**：导出的包在本地按 README 能跑起来；分享链接为只读且不可枚举。
- **降级**：导出格式降级为单文件可运行 HTML + Spec JSON。

### S9 · 交付与复测 ⏱ 70min
- **对应模块**：M10
- **产出**：README、说明文档（实现思路/取舍/完成度/后续优先级）、演示录屏、陌生人 5 分钟复测。
- **DoD/Gate**：陌生人仅凭在线链接，在 5 分钟内完成一次完整主流程。
- **降级**：时间不足 → 优先保"链接可用 + README + 说明文档"，录屏可后补。

## 10. 全局工程约定

**环境变量清单（命名与用途，不含具体值）**

| 名称 | 用途 | 是否可暴露到客户端 |
|---|---|---|

**密钥红线（不可协商）**
1. 绝不提交任何 `.env*` 文件；仓库必须含 `.gitignore` 且先于任何密钥写入。

**其他约定**

- **提交规范**：小步提交，每阶段末打一个 tag（便于展示工程过程）。
- **可访问性**：键盘可达、对比度达标、焦点可见（属于"用户体验"细节得分）。

## 13. 模块间接口契约（内部）

> §5（API 契约）与 §6（事件协议）是**对外契约**；本节是**模块之间**的内部契约。
> **这是模块化的强制边界**：模块之间只能通过本节定义的接口通信，**否则视为架构违规**。
> 实施时，`04` 中每个模块的子任务都必须落到本节某个接口上。

### 13.0 三条铁律

1. **依赖方向单一**：只允许"上层 → 下层"或"同层通过接口"，**禁止反向依赖与循环依赖**（如 Store 不得调用 Orchestrator）。
2. **单一写者**：每个数据实体**只有一个模块拥有写权限**（见 §13.6 数据所有权矩阵）。
3. **接口即契约**：接口的输入 / 输出 / 错误语义发生变更，必须走 §14 的变更流程，并检查全部消费方。

### 13.1 接口总表

| 编号 | 接口 | 提供方 | 消费方 | 一句话职责 |
|---|---|---|---|---|
| **I-01** | AuthService | M1 | 所有 API 入口 | 身份识别与请求归属校验 |
| **I-02** | ProjectService | M1 | M2 / M3 / M5 / M7 / M13 / M10 | 项目增删改查 + 持有"当前 Spec 版本"指针 |
| **I-03** | SessionService | M2 | M4 / M10 | 会话与消息读写 |
| **I-04** | RunOrchestrator | M4 | M2 / M10 / M12 | 启动 / 暂停 / 确认 / 取消 / 继续一次 Run |
| **I-05** | EventStream | M4 | M2 / Agent 时间线 / M12 | 事件广播 + 断线续传 + 快照对齐 |
| **I-06** | AgentRole | M4 | 5 个角色实现 | 角色统一输入输出契约 |
| **I-07** | **LLMProvider** | M9 | M3 / M4 / M7 / M8 | **LLM 调用的唯一出口**（Mock / DeepSeek / BYOK 同构） |
| **I-08** | **StoreProvider** | M9 | 所有模块 | **数据读写的唯一出口** |
| **I-09** | **SpecService** | M5 | M4 / M6 / M7 / M8 / M13 | Spec 生成、读写、版本化（不可变） |
| **I-10** | SpecValidator | M5 | M4 / M8 | Spec 结构与语义校验 |
| **I-11** | **SpecRenderer** | M5 | M6 | Spec → 可交互应用（确定性、无副作用） |
| **I-12** | **PreviewBridge** | M6 | 宿主 UI | 宿主 ↔ 预览 双向消息 + 错误回传 |
| **I-13** | AppDataService | M5 | 生成物运行时 / M13 | 生成应用的数据读写（AppRecord） |
| **I-14** | **Verifier** | M8 | M4 / M12 / M10 | 校验执行与报告产出 |
| **I-15** | Exporter | M13 | M1 / M10 | 导出可运行源码包 |
| **I-16** | ShareService | M13 | 外部访问者 | 只读分享链接的签发与校验 |
| **I-17** | QuotaGuard | M11 | M4 / M9 | 限流、预算、熔断判定 |
| **I-18** | Observability | M12 | 所有模块 | 日志、事件持久化、耗时与用量 |

### 13.2 关键接口的输入 / 输出契约

**I-07 LLMProvider**（全项目最关键的接口）

| 项 | 约定 |
|---|---|
| 输入 | 角色标识、系统约束、上下文片段、**期望输出结构（schema）**、超时、本次预算 |
| 输出 | 结构化结果 + 用量（token）+ 耗时 + provider 标识 |
| 错误语义 | **四类必须可区分**：超时 / 限流 / 结构不合法 / 内容被拒（上层的重试策略不同） |
| 不变式 | ① 上层**不得**出现任何 provider 名称的分支判断；② Mock 与真实 provider **输出同构**；③ 每次调用都计入用量统计（供 I-17 熔断） |
| 实现方 | Mock / DeepSeek / BYOK（三者同一契约，可热切换） |

**I-08 StoreProvider**

| 项 | 约定 |
|---|---|
| 输入 | 实体类型、操作、查询条件、分页 |
| 输出 | 实体或集合；写操作返回持久化后的实体（含 `id` / `updatedAt`） |
| 错误语义 | 未找到 / 冲突 / 连接失败 / **版本不兼容** |
| 不变式 | ① 所有实体带 `schemaVersion`；② 低版本读取必须**兼容或明确报"版本不兼容"**，禁止静默失败；③ 更换实现（托管 DB / 本地 SQLite / IndexedDB）**不改上层** |

**I-09 SpecService**

| 项 | 约定 |
|---|---|
| 输入 | 新建：契约 + 页面清单 + 数据模型；读取：项目 + 版本号 |
| 输出 | 带版本号的 Spec |
| 不变式 | ① **Spec 不可变**——修改产生新版本，绝不原地改；② 新版本必须记录 `parentVersion` 与 `changeSummary`；③ **项目指针归 M1、Spec 内容归 M5**，职责不重叠 |

**I-11 SpecRenderer**

| 项 | 约定 |
|---|---|
| 输入 | Spec + 数据访问句柄 |
| 输出 | 可交互界面 |
| 错误语义 | 结构非法 / **组件不支持** / 数据访问失败 |
| 不变式 | ① **同一 Spec 两次渲染结果确定**；② 组件必须来自白名单，**不支持即报错，禁止静默近似**；③ 渲染器**不得访问宿主内部状态** |

**I-12 PreviewBridge**

| 项 | 约定 |
|---|---|
| 宿主 → 预览 | 装载 Spec、注入数据、请求刷新 |
| 预览 → 宿主 | 运行时错误、未处理异常、资源失败、数据变更请求、尺寸变化 |
| 不变式 | ① **预览内的错误必须回传**，禁止静默白屏；② 沙箱**不授予同源权限**；③ 消息带版本号，过期消息丢弃 |

**I-14 Verifier**

| 项 | 约定 |
|---|---|
| 输入 | Spec（含版本）+ 需求契约 |
| 输出 | 报告：`passed[]` / `failed[]`（含严重级别与原因）/ `unverified[]` |
| 错误语义 | 校验器自身异常 → 返回 `unverified`，**绝不计为通过** |
| 不变式 | ① 报告必须可持久化为 Artifact；② "部分通过"必须在 UI 可见；③ 修复轮次由 M4 控制，**上限 2 轮** |

**I-17 QuotaGuard**

| 项 | 约定 |
|---|---|
| 输入 | 调用方标识、预计消耗 |
| 输出 | 允许 / 拒绝 + 原因 |
| 不变式 | ① 拒绝必须可解释（人话）；② 触发全局熔断时**自动切 Mock**并在 UI 显式标注 |

**I-06 AgentRole**（5 个角色统一签名）

| 项 | 约定 |
|---|---|
| 输入 | 角色上下文 + 上游 Artifact + 期望输出 schema |
| 输出 | Artifact + 用量 |
| 不变式 | 角色**不得直接访问 Store 或 LLM**，必须经由 I-08 / I-07 |

### 13.3 依赖方向规则

```
UI 层（M1/M2/M3/M6/M7/M13 的界面）
  └─→ API 层（§5 对外契约）
        └─→ 编排层（M4）
              ├─→ 智能体角色（I-06）
              │     └─→ 适配器层（M9：I-07 LLMProvider ／ I-08 StoreProvider）
              └─→ 生成物运行时（M5 SpecRenderer ─→ M6 预览沙箱）

横切（任何层都可依赖）：I-17 QuotaGuard、I-18 Observability
```

**禁止**：适配器依赖编排层；渲染器依赖宿主状态；**任何模块绕过 I-08 直接读写数据库**；UI 直接调用 LLM。

### 13.4 跨模块数据流（关键时序）

| 阶段 | 跨模块链路 |
|---|---|
| 提交需求 | M1(I-01 鉴权) → M2(I-03 建消息) → M4(I-04 建 Run) |
| 出计划 | M4 → I-07(LLM) → Artifact(plan/contract) → M4 **挂起等待确认** |
| 生成 | M4 → 角色序列(I-06) → I-09(Spec 落库为新版本) → I-05(事件) → M12(留痕) |
| 预览 | M4 → I-11(渲染) → M6(沙箱) → I-12(错误回传) |
| 校验 | M4 → I-14(校验) → 报告 Artifact →（未通过）→ I-07(修补) → 新版本 |
| 迭代 | M7 → I-09(定位并增量修改片段) → 新版本 → I-11 重新渲染 |
| 导出 | M13 → I-09(读 Spec) → 打包 → 下载 |
| 应用数据 | 生成物界面 → I-13 → I-08 → AppRecord |

### 13.5 接口稳定性与版本

- 接口以 `I-xx` 编号标识，**编号不复用**。
- 契约变更（输入 / 输出 / 错误语义）必须：① 更新本节；② 递增本文档版本号；③ **逐一检查所有消费方**。
- 新增可选字段 ＝ 兼容变更；删除字段或改变语义 ＝ **破坏性变更**，必须同步修改消费方。

### 13.6 数据所有权矩阵（单一写者原则）

| 实体 | **唯一写入方** | 允许读取方 | 备注 |
|---|---|---|---|
| User | M1 | M1 | 密码只存哈希 |
| Project | M1 | M2 / M3 / M5 / M7 / M10 / M13 | M1 持有"当前 Spec 版本"指针 |
| Session / Message | M2 | M4 / M10 | |
| Run | M4 | M2 / M8 / M10 / M12 | **状态迁移只能由 M4 执行** |
| Artifact | M4（代角色写入） | M3（契约）/ M8（报告）/ M10 / M12 | 角色**不直接**写库 |
| SpecVersion | M5 | M4 / M6 / M7 / M8 / M13 | **不可变，只新增版本** |
| AppRecord | M5（经 I-13） | 生成物运行时 / M13 | 与宿主同库 |
| EventLog | M12 | M4（回放）/ M10 | `eventId` 单调递增 |

> **越权写入即架构违规**。评审时可以用一句话检验模块边界是否被破坏：**"这个实体谁能写？"**
