## 1. 我理解的题目

题目要求实现一个**可运行的网页应用**，具备类似 Atoms 的能力与 UI 交互体验：
**通过智能体驱动的方式完成应用生成，并把生成的应用以可视化网页形式展示**；
同时要求**真实交互**、**数据持久化**、**至少一个延展能力**，且必须是"实际可用的功能"而非 PoC。

我把这句话翻译成三条不可让渡的支柱：

1. **Agent 驱动且过程可见** —— 不是"输入框套一次模型调用"
2. **产物是真应用** —— 能点、能填、能存，不是文档或截图
3. **可视化实时展示** —— 同一界面内渲染并可操作

## 2. 实现思路

### 2.1 一句话概括

> 智能体不直接编写整个工程，而是产出**结构化 App Spec**；由**同一个确定性渲染运行时**
> 把 Spec 渲染成真应用——因此它**稳定、可机检、可增量修改**，并且能**被导出带走**。

### 2.2 主管线

```
用户需求
  → ① Planner（Mike）      执行计划
  → ② 需求契约             必做 / 禁做 / 验收点（★ 每条带可机检断言）
  → ③ 【人工确认 Gate】     未确认不执行
  → ④ PM（Emma）           页面与信息架构
  → ⑤ Architect（Bob）     数据模型
  → ⑥ Engineer（Alex）     App Spec（结构化）
  → ⑦ Verifier（QA）       结构校验 + 渲染冒烟 + 契约逐条核对
  → ⑧ 自愈（≤2 轮）         最小改动修复；修不好就如实上报
  → 收敛：落库为版本 → 预览更新
```

关键实现选择：**前端驱动的"短步骤"执行**。每次 HTTP 请求只推进一步（一次模型调用 + 一次落库），
由前端循环驱动。这让单请求永不触发 Serverless 函数超时，**任何平台都能跑**，
同时让"过程可见"成为天然结果，而不是额外做一套进度条。

### 2.3 三处最关键的取舍

**取舍一：结构化 Spec 驱动，而不是让 LLM 自由生成整个工程。**

自由生成更"像"Atoms，但它把三个风险同时放大：产物不可校验、增量修改容易改坏、预览容易白屏。
而我要拿的恰恰是"稳定性 + 可验证性"。代价是**表达力有边界**——所以我把边界写明为组件白名单，
**超范围时明确报错**，而不是悄悄降级成近似物。

**取舍二：需求契约带"可机检断言"，而不是一段自然语言描述。**

这是我对冲同类产品"需求漂移"与"报错却宣称完成"的核心手段。契约里每一条都带
`check` 断言（组件存在性、动作能力、字段类型、集合数量上限……），由 Verifier 逐条机检。
**无法机检的要求会被明确列入"未校验"，绝不计为通过**——宁可显示"我校验不了"，也不谎报成功。

**取舍三：渲染运行时用原生 JS 写，不用 React。**

因为同一份代码要被**三个场景**复用：沙箱 iframe 预览、导出包离线运行、测试断言。
原生 JS + 无构建步骤让"导出即所得"成为可能：导出的单文件 HTML 里内联的就是**同一份运行时**，
不存在"预览能跑、导出跑不起来"的漂移。

### 2.4 工程细节上的几个决定

- **零原生依赖**：用 Node 24 内置的 `node:sqlite`，避免在 Windows 上编译原生模块（这是限时项目里最容易被吃掉一小时的坑）
- **预览鉴权用短期令牌而非 Cookie**：沙箱 iframe 不授予同源权限，跨源请求不会带 Cookie；令牌既保住严格沙箱，又让生成的应用真实读写数据
- **回滚以"新版本追加"实现**：历史版本永不删除，版本链始终可回溯，且**不动生成物的数据**
- **导出提供两种形态**：单文件 HTML（双击即可离线运行，无需构建）＋ 多文件工程 ZIP
  （index.html 外链 app-runtime.js + spec.json + README.md，结构上更接近真实源码工程）
- **存储层用可插拔执行器**：`SqlExecutor` 隔离"如何连数据库"，`SqlStore` 只写一次 SQL；
  本机用 `node:sqlite`，Serverless 用 Turso（纯 `fetch`）——同一套业务代码，无需分支
- **公网自保**：限流 + 单 Run 预算 + 每日全局熔断（超出自动切 Mock），避免自备额度被陌生人烧光

## 5. 给评审的走查指引

见 `README.md` §3「五分钟走查路径」。最短路径：

1. 首页点 **一键体验** → 点示例 **「个人待办清单」**
2. 看左栏智能体时间线逐步推进 → 在**需求契约**页点 **确认**
3. 右栏预览里**新增一条任务、切换完成状态**
4. **刷新页面** —— 项目、产物与刚录入的数据都还在
5. 输入「给这个应用增加一个优先级字段」→ 产生 v2 → 在**版本与迭代**里**回滚**，数据不丢
6. 点右上角 **导出单文件应用** → 下载 HTML，双击离线运行

**建议重点看三处**（这是我与同类产品拉开差距的地方）：

- **需求契约**页：必做/禁做/验收点都是**可机检**的，不是一段自然语言
- **校验报告**页：通过项、未通过项、以及**"未校验"**项分列——校验不了的会明确说校验不了
- 故意问一个超出能力的需求（例如"接入企业微信并同步组织架构"）：系统会**如实标注诉求未被自动落地**，而不是假装完成
